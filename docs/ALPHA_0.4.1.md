# 0.4.1 Alpha

이번 알파는 연결을 직접 사용하고 피드백으로 개선하는 단계입니다. 모든 공급사의 실계정 검증이 끝나야 배포하는 방식으로 진행하지 않습니다. 공개 화면에서 확인한 규격과 합성 테스트를 바탕으로 합리적인 가정을 적용하고, 실제 응답이 다르면 해당 부분을 고칩니다.

## 달라진 점

- 검침 제출 요청이 HTTP 오류 때문에 내부적으로 반복되지 않도록 수정했습니다.
- 공급사 제출 응답이 불분명하면 거절로 단정하지 않고 결과를 다시 조회합니다.
- 가스앱의 잘못된 검침 상태나 자릿수는 제출 단계에서 안내합니다. 청구 조회는 계속 사용할 수 있습니다.
- 같은 달에 여러 청구가 있으면 모두 표시합니다. 서로 합산 가능한지 알 수 없으면 임의의 합계를 표시하지 않습니다.
- 청구 사용량은 이력에서 확인할 수 있습니다. 계량기 지침 추정에는 같은 계량기의 누적 지침 차이와 직접 확인한 숫자를 사용합니다.
- 이전 버전이 청구에서 복제한 추정 기간도 업그레이드와 백업 복원 시 구분합니다. 원래 청구와 직접 입력한 기간은 유지합니다.
- 기기 시간이 뒤로 바뀌어도 저장 기록을 읽을 수 있고, 중단된 저장 작업의 복구 파일을 먼저 확인합니다.
- 작년 이력을 사용하는 추정에도 최근 확인 기록의 강건 기울기를 반영했습니다.
- 연결 실험실에서 진행 중인 조회를 취소하고 다시 실행할 수 있습니다.
- 진단 기록과 실험 결과에서 피드백 초안을 공유할 수 있습니다. 선택한 앱에서 내용을 확인하고 직접 전송합니다.

## 이번 알파의 가정

가스앱은 선택적인 제출 여부, 채널 변경과 계량기 교체 플래그가 없으면 기존 웹 흐름에 맞춰 false로 처리합니다. 숫자형 플래그 0과 1도 지원합니다. 자릿수 자체가 없으면 앱의 지침 범위 제한을 사용합니다. 실제로 전달된 값의 형식이 잘못된 경우에는 그 값을 정상 상태로 추정하지 않습니다. 제출에 필요한 기간, 계약, 계량기와 이전 지침은 확인합니다.

가스앱 청구의 월과 수치는 공급사 응답을 표시합니다. 보정 사용량을 원시 계량기 사용량으로 간주하거나 날짜가 있다는 이유만으로 현재 계량기의 추정 이력에 합치지는 않습니다. 같은 달의 여러 행은 분할 청구나 재고지일 수 있어 각각 표시하고 피드백을 받습니다.

삼천리의 실험적 조회와 경남·대성·에너지톡 연결 실험은 계속 제공됩니다. 일부 공급사의 실제 계정 응답이 아직 없다는 사실만으로 기능을 숨기지 않습니다. 미지원 부분과 가정은 화면과 문서에 남깁니다. 해양의 네이티브 인증 해독처럼 실행 가능한 규격 자체가 없는 부분은 별도 구현 과제로 유지합니다.

## 피드백 방법

1. 본인이 사용하는 공급사를 선택해 연결을 시도합니다.
2. 조회된 월, 금액과 사용량을 공식 사이트 또는 고지서와 비교합니다.
3. 실험실 또는 설정의 진단 기록에서 `피드백 초안 보내기`를 누릅니다.
4. 성공 여부, 기대한 동작과 실제 동작을 적어 [GitHub 이슈](https://github.com/mahlernim/gas-self-meter-ai/issues) 또는 [테스터 그룹](https://groups.google.com/g/gas-self-meter-ai)에 전달합니다. 고객번호, 주소와 인증정보는 제외합니다.

앱은 피드백이나 조회 결과를 자동 전송하지 않습니다. 제공한 피드백을 바탕으로 회사별 필드, 단위와 흐름을 수정합니다. 가입, 로그인과 실제 검침 제출은 공급사의 상태를 바꿀 수 있습니다. 검침 제출은 정확한 값을 직접 확인하고 실행하며, 결과가 불분명하면 재전송하지 않고 공식 상태를 확인합니다.

실제 공급사 거래 성공과 로컬 합성 테스트 통과는 구분합니다. 전체 실계정 검증은 이번 알파 배포의 선행 조건이 아니며 후속 피드백 과제입니다.
